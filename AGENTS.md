# AGENTS.md — DEEIX-RU

Инструкции для ИИ-агента (OpenCode, Claude Code и т.п.), который сопровождает проект DEEIX-RU. Сначала прочитай этот файл целиком, потом нужные разделы в `docs/`.

## Что это за проект

Владелец — Kimi. Он держит на своём VPS чат [DEEIX Chat](https://github.com/DEEIX-AI/deeix-chat) (сайт `tap.teamdream.online`) и дорабатывает его под себя: русский интерфейс, правки интерфейса, чтение документов, OCR, маскировка персональных данных, юридические скиллы и MCP-инструменты.

## Как общаться с Kimi

- По-русски, просто и коротко, без жаргона. Kimi не программист: объясняй, что изменится для него, а не как устроен код.
- Сначала результат или вопрос, потом подробности.
- Если есть выбор, который меняет задумку, предложи 2–3 варианта и порекомендуй один.
- Секреты, пароли, ключи API не проси и нигде не записывай. Ключи Kimi вписывает сам (`/etc/*.env`, админка DEEIX).
- Не предлагай снова то, от чего Kimi отказался (например, MCP ЕГРЮЛ — см. `docs/zametki/egrul-kad.md`).

## Как работать с VPS

У агента **нет доступа к серверу**. Команды выполняет Kimi в веб-терминале 1Panel. Поэтому:

- Каждая команда для терминала начинается с `clear` и даётся **одним блоком через `&&`** (а не по строчке).
- Длинные скрипты в веб-терминал вставляются криво: лучше отдать файлом (загрузить через 1Panel → «Файлы»), запустить и удалить.
- Перед заменой чего-либо — копия с понятным именем (`out-pered-28`, `deeix-chat-pered-28`, `deeix-pd-mask:pered-28`), к инструкции — команда отката и команда уборки.
- Не оставлять «хвостов»: временные файлы, клоны, старые копии удалять, когда они больше не нужны.
- `apt upgrade` запускать с `DEBIAN_FRONTEND=noninteractive`, иначе в веб-терминале всплывают вопросы debconf.
- Время на сервере — UTC (Москва = UTC+3). Время под ответом в чате = время окончания, `created_at` в БД = начало.

Устройство сервера, пути, контейнеры и порты: [`docs/vps.md`](docs/vps.md).

## Правила для PR

- **deeix-ru-build: сливать только после явного «да» / «сливаем» от Kimi.** Обычный путь: PR → зелёная сборка → инструкция по установке → Kimi ставит на VPS и проверяет → Kimi говорит «сливай» → squash merge.
- **tap-shell: сливать самому без согласия**, если пробная сборка на ветке зелёная (решение Kimi от 2026-10-23). Каждый раз поднимать `versionName` (см. `tap-shell/AGENTS.md`).
- Описание PR — по-русски: что сделано, как проверено.
- В репозитории (он публичный!) не должно быть ключей, паролей, токенов, внешних IP сервера, личных данных и файлов пользователей. Проверяй `git diff` перед коммитом.

## Как устроен аддон и сборка

Коротко (подробно — [`docs/sborka.md`](docs/sborka.md)):

1. Исходники аддона лежат **в архиве** `deeix-ru-addon.tar.gz` (папка `deeix-ru-addon/`: `install.sh`, `patches/*.patch`, `files/`, `tools/`, `README.md`). Чтобы что-то поменять: распаковать, править, проверить, запаковать обратно (`tar -czf deeix-ru-addon.tar.gz deeix-ru-addon`) и закоммитить архив. Распакованную папку не коммитить.
2. `install.sh <путь к клону deeix-chat>` накладывает патчи через `git apply` по порядку и копирует `files/`. Каждый патч, кроме `ru-locale`, отключается ключом `--no-<имя>`. Порядок важен: поздние патчи зависят от ранних (`word-revisions` нужен `doc-text`, `ocr-text` нужен `scan-pdf`).
3. Новая правка = **новый патч** `patches/<имя>.patch` + ключ `--no-<имя>` в `install.sh` + раздел в `deeix-ru-addon/README.md`. Русские строки — в `files/apps/web/i18n/messages/ru-RU/*.json`, английские/китайские — в самом патче.
4. Сборка: workflow `build.yml` (запуск вручную, `workflow_dispatch`, вход `tag` = версия DEEIX на сервере, сейчас `v0.4.6`). Артефакты: `deeix-ru-out` (сайт) и `deeix-ru-backend` (бинарник). Ветку PR можно собрать: `gh workflow run build.yml --ref <ветка> -f tag=v0.4.6`.
5. Образы `deeix-ocr` и `deeix-pd-mask` собираются своими workflow (`ocr-image.yml`, `pd-mask-image.yml`) на PR с изменениями в их папках, артефакт — tar образа.
6. Проверка перед PR: аддон встаёт на чистый клон тега (`install.sh`), `go build ./... && go test ./...` в `backend` (нужен Go 1.26, `GOTOOLCHAIN=auto`), `pnpm --filter @deeix/web check` (архитектурные правила: без необъяснённых `as`, `shared` не зависит от `features`, хуки чата называются `use-chat-*`).
7. Изменения во фронтенде требуют только новый `out`, в бэкенде — новый бинарник.

## Как отдавать работу Kimi

Для каждой правки, которую надо поставить на сервер, пиши инструкцию `docs/instrukcii/<фича>/ustanovka.md` по образцу [`docs/instrukcii/pd-preview/ustanovka.md`](docs/instrukcii/pd-preview/ustanovka.md):

1. Ссылки на PR и на запуск сборки, какие артефакты скачать.
2. Куда положить zip (1Panel → «Файлы» → `/opt/deeix-ru/`).
3. Одна команда установки (с копией старого и проверкой «новый код: N» через `grep -c <строка из нового кода> /opt/deeix-ru/deeix-chat`, в конце `curl -s http://127.0.0.1:8080/healthz`).
4. Что проверить на сайте (Ctrl+F5).
5. Откат и уборка.
