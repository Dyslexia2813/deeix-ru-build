# DEEIX-RU — PDF-сканы без текстового слоя (2026-10-15)

## Проблема
В DEEIX-Chat v0.4.4-beta.4 PDF без текстового слоя при загрузке получает «Ошибка обработки · PDF…» и не отправляется в чат. Причина: `pdf_ocr_fallback_enabled=false` (по умолчанию) → экстрактор возвращает `pdf_no_extractable_text` → статус файла `failed` → `hydrateAttachmentsForSend` отклоняет отправку. Картинки проходят, потому что идут как vision-вход без OCR (`ExtractStatus none`, `ProcessingReady true`).
В контейнере `deeix-chat-app` нет pdftoppm/mutool/magick, поэтому OCR через LLM (рендер страниц) недоступен.

## Решение: `patches/scan-pdf.patch` в аддоне (только бэкенд)
- Чистый Go, без новых зависимостей (pdfcpu v0.13.0 и x/image уже в go.mod).
- Новый пакет `infra/extraction/pdfpageimages`: достаёт самое крупное встроенное JPEG/PNG на странице, учитывает /Rotate, при необходимости уменьшает.
- Загрузка: PDF без текста, но с картинками → файл «готов» (`pdf_scan_direct`, ExtractStatus none) вместо ошибки.
- Отправка: страницы прикрепляются к запросу как изображения (до 30 страниц, 64 МБ исходник, сторона не меньше 1600 px) с пометкой в контексте.
- `install.sh` применяет оба патча; `--no-scan-pdf` отключает этот.

## Проверка
- Пакет pdfpageimages: unit-тесты проходят в изолированной сборке (8 тестов).
- Патч применяется на чистый тег в обоих порядках с ru-locale.patch, install/check/uninstall проверены.
- Весь бэкенд локально не компилировался (Go-прокси недоступен), gofmt чист. Реальная компиляция — на GitHub Actions; при ошибке нужен лог.

## Ограничения
Только текущее сообщение (в следующих скан заново не отправляется); JBIG2 и JPEG 2000 не поддерживаются (останется ошибка); у страниц из фрагментов берётся самое крупное изображение; старые файлы с ошибкой нужно загрузить заново; модель должна понимать изображения.
