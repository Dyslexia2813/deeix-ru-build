# Установка: маскировка ПД (PR #27)

PR: https://github.com/Dyslexia2813/deeix-ru-build/pull/27
Сборка образа: https://github.com/Dyslexia2813/deeix-ru-build/actions/runs/43490463025, артефакт `deeix-pd-mask-image`.

Ставится одна вещь: контейнер `deeix-pd-mask`. Он стоит между DEEIX и провайдером. Когда в чате включена «Маскировка ПД», он заменяет ФИО, телефоны, почту, ИНН, ОГРН, СНИЛС, паспорт, карты, счета, даты рождения и адреса метками вида `[FIO_k3m9q]`. В ответ модели и в аргументы инструментов он возвращает настоящие данные. Сайт, бэкенд и база DEEIX не меняются, патча DEEIX нет: переключатель — штатная возможность DEEIX v0.4.6.

Сколько это стоит: в простое около 2 МБ памяти, под нагрузкой единицы мегабайт (лимит контейнера 96 МБ), образ 7 МБ. Маскировка запроса в 400 КБ занимает миллисекунды. Денег не стоит.

## Шаг 1. Скачать и загрузить
1. По ссылке на сборку выше (раздел Artifacts внизу) скачайте `deeix-pd-mask-image`, придёт `deeix-pd-mask-image.zip` (около 3 МБ).
2. В 1Panel откройте «Файлы» → `/opt/deeix-ru/` и загрузите туда zip. Если браузер добавил к имени « (1)», уберите это.

## Шаг 2. Маршруты
Прокси нужно знать, куда отправлять запросы. Каждый маршрут — это короткое имя и хост провайдера, без пути. Посмотрите в Админке → «Апстримы» базовые URL тех источников, где нужна маскировка. Например:

| Сейчас в «Базовый URL» | Маршрут | Новый «Базовый URL» |
|---|---|---|
| `https://api.deepseek.com/anthropic` | `ds=https://api.deepseek.com` | `http://deeix-pd-mask:8090/ds/anthropic` |
| `https://api.deepseek.com` | `ds=https://api.deepseek.com` | `http://deeix-pd-mask:8090/ds` |
| `https://api.z.ai/api/paas/v4` | `zai=https://api.z.ai` | `http://deeix-pd-mask:8090/zai/api/paas/v4` |
| `https://агрегатор.ru/v1` | `agg=https://агрегатор.ru` | `http://deeix-pd-mask:8090/agg/v1` |

Правило простое: хост заменяется на `http://deeix-pd-mask:8090/имя`, а путь после хоста остаётся как был.

## Шаг 3. Одна команда в терминале 1Panel
В начале команды, в `R='…'`, впишите свои маршруты через `;`. Команда загружает образ, создаёт настройки со случайным секретом и `compose.pd.yml`, запускает прокси и проверяет его.

```
clear && R='ds=https://api.deepseek.com;zai=https://api.z.ai' && cd /opt/deeix-ru && unzip -o -q deeix-pd-mask-image.zip && gunzip -c deeix-pd-mask-image.tar.gz | docker load && rm -f deeix-pd-mask-image.tar.gz && ( test -f pd-mask.env || printf 'PD_SECRET=%s\n' "$(openssl rand -hex 16)" > pd-mask.env ) && sed -i '/^PD_ROUTES=/d' pd-mask.env && echo "PD_ROUTES=$R" >> pd-mask.env && chmod 600 pd-mask.env && printf 'name: deeix-pd-mask\nservices:\n  pd-mask:\n    container_name: deeix-pd-mask\n    image: deeix-pd-mask:latest\n    restart: unless-stopped\n    env_file: /opt/deeix-ru/pd-mask.env\n    mem_limit: 96m\n    memswap_limit: 96m\n    cpus: 0.5\n    pids_limit: 64\n    read_only: true\n    networks: [deeix-chat]\nnetworks:\n  deeix-chat:\n    external: true\n    name: deeix-chat-network\n' > compose.pd.yml && docker compose -f compose.pd.yml up -d --force-recreate && sleep 3 && docker exec deeix-pd-mask /deeix-pd-mask healthcheck && echo "Прокси: работает" && docker logs --tail 3 deeix-pd-mask
```

Должно получиться: `Прокси: работает` и строка журнала со списком маршрутов. Что DEEIX видит прокси, покажет проверка в шаге 5.

Секрет `PD_SECRET` создаётся один раз и при повторном запуске команды не меняется. Не меняйте его и потом: от него зависят метки, и при смене модель в уже начатых чатах увидит новые метки для тех же людей.

## Шаг 4. Настроить DEEIX
1. **Источник.** Админка → «Апстримы» → нужный источник → «Базовый URL»: впишите новый адрес из таблицы в шаге 2 и сохраните. Ключ API не трогайте, прокси передаёт его как есть. Без включённой маскировки запросы проходят через прокси без изменений, поэтому другие модели этого источника работают как раньше.
2. **Переключатель.** Админка → «Модели» → модель → «Возможности модели». В JSON добавьте ключ `controls` рядом с остальными (если `controls` уже есть, добавьте в его список один элемент):

Если поле пустое, вставьте целиком:

```json
{
  "controls": [
    {"id": "pd_mask", "type": "toggle", "label": "Маскировка ПД",
     "description": "Прятать ФИО, ИНН, телефоны и другие ПД перед отправкой модели",
     "icon": "shield", "placement": "menu",
     "on": {"patch": {"deeix_pd_mask": true}}, "off": {}}
  ]
}
```

Если там уже есть другие ключи, добавьте `"controls": [ … ]` внутрь тех же фигурных скобок через запятую. По умолчанию переключатель выключен. Чтобы в новых чатах он был сразу включён, добавьте в элемент `"default": "on"`.

Например, у GLM получится `{"inputModalities":["text","image"],"contextWindow":1000000,"controls":[ … ]}`. Сохраните. Повторите для каждой модели, где нужна кнопка.

**Важно:** добавляйте переключатель только моделям, у которых источник уже идёт через прокси (пункт 1). Иначе флаг уйдёт провайдеру, а данные останутся открытыми.

3. **Названия чатов и сжатие истории (по желанию).** DEEIX сам отправляет модели начало чата, чтобы придумать название, и старую историю, чтобы её сжать. Эти запросы идут без переключателя, то есть без маскировки. Если это важно, заведите маршрут, который маскирует всё: добавьте в `R` запись вроде `ds-all=https://api.deepseek.com always`, повторите команду шага 3 и создайте отдельный источник с адресом `http://deeix-pd-mask:8090/ds-all/anthropic` и одну модель на нём (видимую только администратору). Её выберите в Админке → «Настройки диалогов» → «Модель для задач» и «Модель для сжатия». Если не уверены, напишите, разберём вместе.

## Шаг 5. Проверить
1. Откройте новый чат с моделью, нажмите «⋯» в поле ввода. В «Параметрах чата» появится «Маскировка ПД» со щитом. Включите её (булавкой можно закрепить кнопку в поле ввода).
2. Напишите: «Кто такой Иванов Иван Иванович, ИНН 500100732259? Повтори его ФИО и ИНН.» В ответе должны быть настоящие ФИО и ИНН. В рассуждениях модели (если они видны) будут метки вида `[FIO_…]`: так и задумано, модель видит только их.
3. Журнал: `clear && docker logs --tail 5 deeix-pd-mask`. На каждый запрос с маскировкой будет строка вроде `masked=2 [FIO:1 INN:1]`. Сами данные в журнал не пишутся.
4. Выключите переключатель и спросите то же самое: новой строки `masked=` в журнале не будет.
5. Проверка, что именно прячется, без модели и без сети:
```
clear && echo "Иванов Иван Иванович, тел. +7 916 123-45-67, ИНН 500100732259, Петровой М.С." | docker run --rm -i -e PD_SECRET=test-secret-0123456 deeix-pd-mask:latest mask
```

## Откат
Верните в «Апстримах» прежние базовые URL и уберите `controls` из возможностей моделей, затем:
```
clear && docker rm -f deeix-pd-mask
```

## Уборка после проверки
```
clear && rm -f /opt/deeix-ru/deeix-pd-mask-image.zip
```
Файлы `pd-mask.env` и `compose.pd.yml` оставьте: в них настройки прокси.

## Что умеет и чего нет
- Протоколы: OpenAI Chat Completions и Anthropic Messages, с потоком и без. Если включить маскировку у модели на другом протоколе (например, OpenAI Responses), запрос не уйдёт: появится ошибка «Маскировка ПД работает только с протоколами…».
- ФИО находится по отчеству или инициалам: «Иванов Иван Иванович» в любом падеже, «Иванов И.И.», «И.И. Иванов», «Иван Иванович», ЗАГЛАВНЫМИ. Полное ФИО и инициалы одного человека получают одну метку. Имя без отчества («Сергей») и фамилия без инициалов не прячутся.
- ИНН, ОГРН, СНИЛС и карты проверяются по контрольной сумме, поэтому обычные числа (суммы, номера договоров, даты) не трогаются.
- Названия организаций, город и адрес без улицы и дома не прячутся.
- Картинки и PDF, которые модель получает как файлы, не маскируются. Текст, который DEEIX достаёт из документов (и своё OCR для текстовых моделей), маскируется.
- Обратно подставляется самая полная форма, которая встретилась в запросе. Поэтому падеж может не совпасть: «договор с Иванов Иван Иванович».
- Если маскировку включить посреди чата, прежние сообщения тоже уйдут модели уже с метками.
