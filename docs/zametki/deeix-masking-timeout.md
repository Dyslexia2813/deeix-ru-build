# deeix-masking-timeout

_Ошибка «HTTP 503 Masking exceeded the request preparation deadline» (masking_timeout) у DeepSeek Flash в DEEIX — источник и обходы._

- 2026-10-22 чат с DeepSeek Flash Latest оборвался после 3 раундов рассуждения и 8 вызовов инструментов: 503, code masking_timeout. Тело запроса ~398 КБ.
- Ошибку отдаёт вышестоящий шлюз (агрегатор), а не DEEIX: в исходниках DEEIX v0.4.5 нет ни «masking», ни masking_timeout. Отметка `_debug bodyOmitted / body_too_large` — это лишь DEEIX не сохраняет в отладку тело больше 128 КБ (backend/internal/ports/llm/debug_snapshot.go), а не причина сбоя.
- Вывод: шлюз маскирует (анонимизирует ПД) запрос до отправки модели и не укладывается в свой срок на большом теле; лимит модели 1M тут ни при чём. Какой агрегатор подключён, на 2026-10-22 не выяснено.
- 2026-10-22 у модели в DEEIX «Контекстное окно» = 128 000 в режиме Авто (не 1M), т.е. сжатие истории уже с ~76 тыс.; запрос разросся внутри одного ответа из-за 8 вызовов инструментов. Маскирование Kimi отключать не хочет.
- Обходы: выключить маскирование у агрегатора или подключить DeepSeek напрямую (api.deepseek.com, протокол OpenAI — см. [deeix-deepseek-anthropic](deeix-deepseek-anthropic.md)); уменьшить окно контекста модели в DEEIX (сжатие раньше); меньше лимит вызовов инструментов. Сжатие DEEIX работает между сообщениями, внутри одного ответа результаты инструментов копятся.
