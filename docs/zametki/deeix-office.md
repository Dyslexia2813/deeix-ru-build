# deeix-office

- 2026-11-20 Kimi попросил, чтобы модель сама собирала Word и Excel по запросу. Выбран короткий список оформления + заливка ячеек: Word — заголовки 1–3, абзацы (выравнивание), жирный/курсив/подчёркнутый (`**`, `*`, `__` в тексте), списки (нумерованные с 1 у каждого списка, маркированные), таблицы (заливка ячеек и заголовка, ширина колонок, заголовок повторяется), разрыв страницы, шрифт и размер документа, поля (по умолчанию 30/15/20/20 мм), номера страниц. Excel — листы, жирная закреплённая строка заголовков с фильтром, ширина по тексту, числа, даты, формулы (`fullCalcOnLoad`), форматы money/percent/date/integer/number/text, заливка.
- Как устроено: MCP-сервер на Go (папка `office/`, только stdlib), контейнер `deeix-office` в `deeix-chat-network`, порт 8095, том `deeix-office-data`, лимит 64m. Инструменты `make_docx`, `make_xlsx` отвечают JSON с `url` и `markdown`; модель вставляет ссылку в ответ. DEEIX v0.4.6 отдаёт модели текст результата MCP как есть (infra/mcp/client.go), файлов от MCP не показывает — поэтому ссылка.
- Скачивание: патч `office-files` (бэкенд) — публичный маршрут `GET /api/v1/office-files/:token/*name` в группе publicAuth (rate limit) → `http://deeix-office:8095/files/...` (`DEEIX_OFFICE_URL`). Исходящий HTTP только в `infra/officefiles` (тест TestHTTPTransportDoesNotOwnExternalIO запрещает его в transport). Доступ по 128-битному токену без входа, 7 дней (`OFFICE_TTL_DAYS`), общий предел 200 МБ.
- Схемы ячеек без `anyOf` (только описание) — на случай провайдеров, которые его не принимают.
- Проверено локально: DEEIX синхронизирует оба инструмента, ссылка из ответа скачивает файл через DEEIX, файлы открываются в LibreOffice/openpyxl/python-docx. 2026-11-20 Kimi поставил на VPS и проверил с живой моделью — работает.
- Возможные доработки (Kimi упоминал как «потом»): колонтитулы, сноски, картинки, цвет текста, режим правок, оглавление; скачивание только после входа.
- Большой файл: GLM (Z.ai) пишет аргументы вызова молча, дольше 60 с → DEEIX рвёт поток («HTTP 200, Сервис апстрима недоступен», в журнале `stream idle timeout`). Лечение: у источника «Тайм-аут простоя потока (мс)» = 300000.
