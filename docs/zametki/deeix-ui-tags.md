# Компонент HTML-тегом в ответе (stat-grid, decision-tree)

- 2026-11-23 Kimi: в ответе модели вместо карточек виден текст `<stat-grid title="Сводка рисков по договору" id="risk-summary" items="[object Object],…" />`, а потом `<decision-tree … nodes="[{"id": "status", …}]" />`.
- Причина: включены одновременно «Промпт визуальной вёрстки» (html-visual) и интерактивные компоненты. Промпт вёрстки велит писать HTML прямо в тексте, а компоненты надо писать блоком ```` ```deeix-ui ```` (JSON). Модель смешала: написала компонент HTML-тегом. Сайт такой тег не знает и по правилу апстрима (`streamdown-raw-html.ts`) показывает его текстом. `[object Object]` модель написала сама — в коде DEEIX и наших патчах такой строки нет; данные этого блока потеряны.
- Решение: `patches/ui-tags.patch` (ключ `--no-ui-tags`). Сайт: `streamdown-ui-tags.ts` превращает отдельно стоящий тег встроенного компонента в блок deeix-ui (атрибуты → поля, JSON читается и с голыми кавычками внутри атрибута, и в виде `items={[…]}`); у таблицы с потерянными столбцами они берутся из полей строк; при потерянных данных показывается обычная карточка «блок не отрисован». Бэкенд: в `routing` промпта вёрстки (`system_prompt.go`) правило «компоненты только блоком deeix-ui, не HTML-тегом».
- Старые ответы тоже исправляются при показе (правка на сайте, база не меняется).
- Не трогает: теги внутри ``` и тег посреди строки текста.
- Связано: [deeix-html-visual](deeix-html-visual.md), [deeix-data-table-fit](deeix-data-table-fit.md).
- 2026-11-24 после установки Kimi увидел карточки «неполные данные»: stat-grid (items потеряны моделью) и data-table (columns потеряны, rows целы). Добавлено восстановление столбцов таблицы из ключей строк.
